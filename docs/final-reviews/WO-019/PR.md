# Make the catalog something to read

## Summary

The catalog is now something to read. Every one of the 3,463 concept rows carries the research run's own definition, its place in the work (part, chapter, section and subsection), its related concepts, the hooks the mapping worker suggested for the platform and the run's verification note, joined from the eleven pinned map files by `npm run catalog:join` with every digest, row count and line identity checked before a byte is written. The allow-list, the string scrub and the length ceilings that refused this content are gone; the `tool-v1` schema still closes every object and refuses unknown fields, and the loader reads `tool-v0` for one more release with an explicit unavailable-definition message.

`/tools/catalog` is a reading surface: a shelf of the six works in their own colours with a concept count and the scene each feeds; a table of contents of chapters, sections and concepts; a reading measure that sets the definition at body size under the title, with the place in small caps, the model-knowledge or partial mark beside a definition the run did not verify, the hooks as sentences, a typed tool's five faces as one sentence with its parameters and their defaults, an untyped tool's reason, the soldier-scene note and the related concepts as links in running text; one search field over titles and definitions, with work, kind and status as facets inside the results and Enter opening the first; and the last ten readings, which persist across a reload under `dotln-angular.tools`. The Tools home names the works, their counts and the last reading. There is no label-value list on the page.

Sixteen AI for Games rows are typed for the soldier scene's rail floor, among them Seek, Arrive, Separation, Velocity matching and Wander as blended steering terms and Slot assignment as a two-level formation parameter set; the summary lists each work's chapters with counts and its scene tools, and `npm run catalog:report` prints the fraction of resolved relations per work (AI for Games 980 of 1,335; Enterprise Integration Patterns 1,073 of 1,088; Patterns of Enterprise Application Architecture 705 of 772; RxJS 821 of 1,382; Gödel, Escher, Bach 482 of 965; Team Topologies 919 of 1,183).

Arrive carries one authored study, marked on the page as created for it and kept apart from the mined definition: a time-scrubbed drawing with Movement and Velocity views of one motion, a worked calculation that follows the timeline, the ordinary pseudocode in full with each step's lines behind a closed disclosure, an RxJS reading with a data-flow and an event-timeline view, a late-braking comparison on one chart, and checked public references with an account of how a game library's Arrive differs. Closed explanations are created on first expansion through `@defer`, download one chunk, and keep their view when collapsed.

The workspace scripts now each state a purpose and a status (in a gate, a helper or a module): CI runs the workspace checks once through `nx run workspace-tools:lint`, the lint-rule fixture tests leave the gate and become a helper, and the checkpoint merge script is deleted with its test. The bundle check also refuses the Angular Aria menu and the CDK overlay in the initial graph. No dependency changes.

- The reading's "runs in the soldier scene" line becomes a link to the scene with the tool chosen when the scene replaces its arriving page.
- Readings are not addressable by URL, so the browser's Back leaves the catalog instead of returning to the previous reading; the in-page return control covers the session. The Tools home loads every catalog chunk to show six titles, six counts and the last reading.
- The Arrive study repeats a few of its model's constants in its drawing and prose, keeps each section's open state in both the native disclosure and the facade, and uses fixed element ids; the concept-study authoring work derives these from the model.
