## Release overview

DotLn-Angular now gets named releases. From its next target order on, the kit's release close tags DotLn-Angular and publishes a GitHub Release titled `DotLn Angular` and its tag, starting with `DotLn Angular v0.1.0`, as the operator directed on 2026-10-19. The same close now keeps the build output and dependencies in the DotLn-Angular clone's base checkout, so that checkout no longer needs a reinstall after every close. The operator's own commits also pass the kit's sign-off rule at publication without a trailer. This is the first Launchpad release under starter v0.88.0, which #16 took after `v0.3.2`. It is for the operator and for the sessions that run, review and close orders here and in DotLn-Angular. `Launchpad v0.3.3` is a patch release. WO-012 changes only configuration, the operator grant and records; the kit code is starter v0.88.0's, taken unchanged.

## Read before upgrading

- Authority change: the `dotln-angular` registration now allows `release.close`, and the operator grant `operator.dotln-angular.publication` names it alongside `repo.push`, `pr.open` and `pr.thread.resolve`. A target close therefore creates an annotated tag and a GitHub Release in DotLn-Angular. Merging, repository settings and package publication stay with the operator. The close reads the registration and the grant from this launchpad's merged `main`.
- Required for every DotLn-Angular order: now that a release policy is declared, each `dotln-angular` order needs exactly one `**Target release classification:**` header naming `patch`, `minor` or `major` on the same line, or its close refuses with `exactly one is needed`. Nothing checks this before the close. WO-006, WO-007 and WO-008 have no header yet; the UI planning pass adds the headers before WO-006 starts. DotLn-Angular's profile gives a two-count check to run before an order starts. That check also rejects a malformed second header, which the kit's own parser admits.
- Base checkout output is kept: under `baseDisposablePolicy: "judge-only"` the close no longer deletes the ignored output under the eleven declared roots (`node_modules`, `.nx`, `dist` and the rest) in the clone's base checkout. It still deletes them in the target worktree, and an undeclared ignored file still refuses the close in either checkout. New refusal: if retained base output collides with a path the fetched base tracks, the close refuses with `judge-only output collides with fetched tracked paths` and leaves the output in place. Move that output away and retry. Returning to the `delete` policy is a separate reviewed change, not an automatic fallback.
- Commit identity: `dotln.config.json` now names the operator's public commit author as `contributions.operatorAuthor`. It is the identity every session commit of this public repository already carries. At `worktree publish`, commits by that author need no sign-off. Every other author's commit needs a `Signed-off-by` trailer matching its author, or publication refuses before any push. A local Git identity setting grants no exemption.
- Starter v0.88.0: for a DotLn-Angular order, registered-target publication is admitted only for `node scripts/worktree.mjs publish WO-NNN --target-worktree …` run from the launchpad root. Raw `git`, `gh` and `npm` forms get no such admission, so WO-006's draft publish must use that spelling. The document gate reads WO-004's and WO-005's moved records through their DotLn-Angular bindings. A named starter release is previewed through a non-tag ref, so no local tag needs deleting afterwards.
- No schema change, removal or launchpad code change comes from WO-012. Required operator action after the merge: `resume: release close` in `main`.

## Substantive changes

- DotLn-Angular releases: the `dotln-angular` registration declares `release: { "policy": "declared", "displayName": "DotLn Angular" }`, and `release.close` moves from its denied effects to its allowed effects. The operator grant adds `release.close` to its effects and operations, and its reason now rests on the operator's directions of 2026-10-17 and 2026-10-19. Both edits are needed: with either one alone the kit still refuses the close.
- Base checkout: `baseDisposablePolicy: "judge-only"` on the registration. The eleven disposable roots the class declares are unchanged.
- Publication sign-off: the top-level `contributions.operatorAuthor` declaration. `historicalWorkOrders` stays undeclared, because WO-001 is a closed order under control.
- Starter v0.88.0 (#16), the kit at core `a54f8d6520ed54d05e5209455c67541562716404`. It carries v0.86.0's gate scheduler and v0.87.0's options that WO-012 declares: target release names, the judge-only base checkout, the operator identity, the node-spelled target publish and the sign-off rule. It also carries v0.88.0's moved-record readers, the `worktree start` advisory for a missing operator identity, the release-close advisory's expected spellings, and commit-lint refusals that print a subject's length beside the 72-character limit.
- Records: DotLn-Angular's profile rewrites its Release close section for the declared policy, and its branch-policy paragraph now routes target tags and Releases through the close. WS-001's WO-012 row links the evidence. The records of WO-005 (DotLn-Angular's foundation libraries, #13) and of the two planning passes that filed and amended WO-012 (#15 and #17) also merged after `v0.3.2`.
