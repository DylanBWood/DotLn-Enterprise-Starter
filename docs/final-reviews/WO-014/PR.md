# The toolbox catalog and its browser

## Summary

The app gains its toolbox. The research run's 3,463 concept rows from six works (AI for Games, Enterprise Integration Patterns, Patterns of Enterprise Application Architecture, RxJS, Gödel, Escher, Bach and Team Topologies) are classified once as tools a unit can be given, scene elements, metrics or background concepts, committed as the app's own data under a schema and an allow-list check, and browsed under Tools at `/tools/catalog`.

- `libs/shared/models`: the readonly `Tool` union with its five faces (scene, selection, transform, observable, toy metric), the closed fourteen-member `TransformKind` enum, the `untyped` transform with its reason, the optional role analog, and the pairing of `map` provenance with a map object and `public-work` provenance with `null`. The library gains a Vitest target for its type spec.
- `libs/shared/catalog` (`scope:shared`, `type:data-access`): eight checkpoint files and a summary under the `tool-v0` JSON schema; `CatalogLoader` behind `CatalogToken` and `provideCatalog()`, loading each work's data as lazy chunks with shared pending promises and eviction on failure so a retry can succeed; pure filters (`byWork`, `byKind`, `byTransform`, `bySceneType`, `byStatus` and `firstThree`, composed from curried selectors); `CatalogStore` over the existing event, call-state and persistence features, persisting only validated filters and the selected id; a `testing` entry point with a three-row fixture and a replaceable loader.
- `tools/scripts/catalog/`: `check-catalog.mjs` validates every checkpoint against the schema with `additionalProperties: false`, refuses definitions, relations, hooks, verification text, chapter and section fields, scrubs every string, checks unique ids, complete source-line coverage, digests and the summary's counts and examples, and reports sanitized locations without values or paths; `merge-checkpoints.mjs` validates every incoming checkpoint before replacing a file; `report.mjs` prints the counts and each work's examples. `npm run catalog:check` runs inside `check:fixtures`, and a negative fixture fails it in `test:tooling`.
- `libs/features/tools` (`scope:dotln`, `type:feature`): `toolsRoutes` with the Tools home over `dotln-key-value-list` and the catalog page over `ToolsFacade`: five filter menus whose work options come from the loaded catalog, a paged tool list of fifty rows, tool details that take focus and return to the selected row, and loading, failure and retry states. `BasePaths.Tools`, `ChildPaths.Catalog`, the Catalog item in the menu's Tools group, and the `tools.*` and `shell.notFound.*` keys.
- The shell's `NotFoundPage` behind the app's last wildcard route: an unknown path such as `/tools/nope` renders a translated not-found page in the main region with a link back to the actor board, where `main` left the region empty and showed the generic error notice.
- Loading: `DotlnMenu` and the new controlled `DotlnFilterMenu` composite move to the `@dotln-angular/ui/menu` entry point, which the lazy Tools route imports statically, and the menu imports its own overlay providers, so the Angular Aria menu and the CDK overlay leave the initial bundle. The menu bounds its height, scrolls internally, falls back above or beside its trigger, and keeps keyboard navigation when a scrolled option lands under a stationary pointer. The `R` and `RA` namespaces export only the functions the app uses (`filter`, `map`, `pipe` and `isNonEmptyString`), with runtime and type assertions over the surface.
- Checks: `npm run check:bundle` builds production with metadata, walks the static imports from the app entry and the global styles, refuses menu, catalog or Tools code in the initial graph, requires the menu to arrive with Tools, and attributes initial bytes by package; it runs in CI and in the preflight. `npm run perf:sample` serves the production build and the recorded board fixture on loopback with precompressed assets and records five samples of three journeys under a desktop and a constrained profile; its journey assertions block and its timings stay diagnostic.
- Documents: `docs/dev-reference/architecture/catalog.md`, `concept-mapping.md` and `performance.md`; `docs/ai-reference/catalog-rules.md`; conventions rule 23; rule R8 in the component rules; the curated-utility and validation-predicate rules in the foundation rules; pointers from both reference roots; two dated entries in the generator log. The command-only utility project is renamed `workspace-tools` so the feature owns the `tools` name.
- Browser coverage: a catalog spec (the board fetching no menu code and the filters needing no further script, filtering by work and by transform kind, an untyped reason, selection surviving a reload, keyboard use and paging, details focus and return, the unknown path with a working board link, keyboard navigation under a stationary pointer at four times CPU slowdown with pointer and touch resuming, axe at the board's threshold, and no horizontal overflow at 360, 768 and 1440), a visual spec with three new baselines, eighteen refreshed baselines that show the Catalog link, and eleven new Storybook entries.
- No dependency changes: Ajv was already installed. Two commits: the reviewed change and the records commit that files the order, its decisions and the verification and review reports under `docs/dotln/`.

## Verification

The catalog was built by eight classifier workers, one per checkpoint, each reading only its map files and the contract; two seeded checkers judged forty typed tools each for observable behavior in a twenty-unit scene; a synthesizer wrote the summary and a critic judged it with three seeded samples; every finding went back to the originating classifier. 121 rows are typed, 1,914 untyped with a specific reason and 1,428 background. Team Topologies has two typed tools and records its shortfall of one: the acceptance criterion was amended on the operator's word to admit up to three typed examples with an explicit shortfall rather than force a transform.

The first independent verification reproduced every criterion against the real maps (digests, per-row identity and text overlap with the run's definitions) and failed one: the production initial bundle had grown from 495.40 kB at the base to 530.37 kB because the menu stack shipped in a chunk the app entry imports statically, for a route most visits never open. The repair moved the menu and its overlay providers to the lazy Tools route, curated the utility exports, added the bundle check and the sampler, and recorded matched builds for every arm. The second verification rebuilt uncached: the initial total is 376.91 kB raw and 102.65 kB estimated transfer with no budget warning, 118 kB below the base, with no menu, overlay, catalog or Tools code in the initial graph and all eight data chunks dynamic; `npx nx run-many -t lint test build` passed uncached across 18 projects, the browser suite passed 76 tests uncached, and the sampler passed 30 journeys. The declared review gate (install, lint, test, format, build, e2e and visual) passed at the verified tree with no tracked-byte mutation.
