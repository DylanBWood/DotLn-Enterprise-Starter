## Release overview

This order ships in DotLn-Angular through its pull request and records no launchpad release; these notes are the five-section surface the publication contract expects, and the target's own release carries them once the order closes. The change: the soldier scene as the app's root and its first toy. Twenty units on a dark field, a rail of the sixteen catalog tools the engine runs with each definition read from the catalog, real-time-strategy selection, flock, arrive and a two-level formation with slot roles, instruments with sparklines, before-and-after trials with the first divergence marked, saved compositions, a deterministic seeded clock, and the pure scene engine behind a renderer seam that every later scene reuses. It is for the operator and the colleagues they show the workspace to: a page to play with, where each movement idea's effect on a group can be seen.

## Read before upgrading

No authority, schema or document root changes in the launchpad, and the `dotln-angular` registration is unchanged. In DotLn-Angular no dependency changes. The root redirects to `/scene` instead of `/board`; the board keeps `/board` under Machinery, and the not-found page links home to the scene. The scene's arriving page is removed, and the `scene.arriving.*` translation keys with it; the `scene.*` block now carries the scene's own strings, mirrored in the feature's test-kit copy. `@dotln-angular/scene/testing` no longer exports `provideSceneTestKit`; it exports `provideSceneFacadeTestKit` and the clock, driver, definition, reduced-motion, renderer-factory and seed-source kits. Two libraries are new, `@dotln-angular/scene-engine` (tagged `type:util`) and `@dotln-angular/scene-data-access`, each with a `testing` entry point, with their aliases in `tsconfig.base.json` and their configurations in the foundation type check. `@dotln-angular/models` exports `sceneTransformKinds`, which the engine's `interpretedKinds` must equal; `@dotln-angular/events` exports `scenePageEvents`. The shared persistence feature gains three optional settings, `writeOn`, `unreadable` and `unwritable`; stores that pass none behave as before. `dotln-button` gains optional `size` and `tone` inputs. The scene persists saved compositions under one new browser storage key, `dotln-angular.scene`, written only when the operator saves; a stored value it cannot read is ignored, reported on the page and left as it is until a save replaces it. `npm run check:fixtures` now runs the scene fixture check before the catalog check. The operator action after both merges is to fast-forward `main`, run the bootstrap, and dispatch `resume: release close` in `main`, which closes the target worktree with the no-release outcome for the launchpad and the target's own release under its declared policy.
