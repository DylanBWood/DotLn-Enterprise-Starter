# Purpose

The refutation goal standard composes the execution guide's marked goal rules
with the one purpose block below; the kit seeds no purpose, so this instance
declares its own.

<!-- dotln-purpose:start -->
This launchpad is the operator's own DotLn instance. Its purpose is to plan and
run bounded, evidence-gated work orders across the operator's repositories, so
that every change arrives as a pull request the operator reads before it merges,
while the kit itself stays upstream and reaches this fork only through starter
updates. The first workstream is DotLn-Angular, an Nx and Angular monorepo that
serves two outcomes at once: the operator's reference Angular workspace, which a
colleague should recognize as the way the operator builds Angular, and the home
of the DotLn console, the Angular shell that will render DotLn's actor-board
view model. The critical path runs from registering that repository in this
launchpad, through one witnessed target order that scaffolds the workspace, to a
foundation where a feature is added by convention: shared libraries, the
component taxonomy, events and stores, and a legitimate client-side
authentication and permission model. Later workstreams join the same way: one
registration and one planning pass each, with the fork's own machinery changes
cut as self orders beside them.
<!-- dotln-purpose:end -->
